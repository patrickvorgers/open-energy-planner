Start developing

Clone the project locally, prepare a tested installation package, then reopen it in VS Code's Dev Container. It runs a separate Home Assistant test installation.

Private repositories require GitHub access inside VS Code. No token belongs in this field.

Opening the clone link sends the repository URL, including any private repository name, to vscode.dev. This page collects no credentials or analytics. Provisioning runs locally.

Clone in VS Code

Prepare your environment

Use an AMD64 (x86-64) environment. ARM hosts need AMD64 emulation and are outside the validated setup.

  1. Install VS Code, Dev Containers and Git. Start Docker with Linux containers.
  2. Install Python 3.12 or newer as python in both your host terminal and VS Code. Check python --version and follow the host interpreter setup if needed. Use the project URL above to clone into a local folder. Keep the folder open locally until package preparation finishes.
  3. Follow package preparation: download the original installation-bundle-amd64 ZIP from a successful Checks candidate merged onto main. Check out its matching verified merge, then run the following in a host terminal from that checkout, replacing both placeholders:

python -m script.supervisor.dev prepare --bundle /path/to/installation-bundle-amd64.zip --run-id RUN_ID

Verification needs existing GitHub read access through Git Credential Manager or GH_TOKEN/GITHUB_TOKEN in your host terminal. Never paste a token into this page.

After preparation succeeds, run python -m script.supervisor.dev start in the same host terminal. This provisions the installation and copies its private login details into your checkout. Then choose Dev Containers: Reopen in Container. Do not clone into a container volume: preparation must run on the host first. Unmerged branches can be edited and tested, but cannot provision a persistent installation.

After setup

Open the local OEP test installation. Developer login details are in .local/dev/developer.json inside the checkout. The EMS uses synthetic inputs and virtual commands.
